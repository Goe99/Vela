# 04 — Issue 详情抽屉

**What to build:** 点一张卡，右侧滑出一个抽屉，占屏幕右侧约四成，Board 仍然留在视野里。抽屉里是这张卡的全部信息：编号、标题、描述、执行配置、以及它历次被派活的记录——每次跑了多久、用了多少 token、结果如何、一个跳去 DSH 看那次会话的按钮。

这也是后面小队时间轴的容器。

## 完成记录

抽屉作为 body 里的右侧一列（四成宽），而不是盖在 Board 上的浮层——浮层会遮住最右
那几列（完成 / 失败），而那正是验收时最想对着看的两列。

**打开方式是卡片标题按钮，不是「整张卡可点」。** 卡上还有删除、派活、编辑表单，
把点击目标放在根节点就得靠猜测意图（排除 button/input/…），这类猜测早晚会错。
副作用是好的：button 天然可聚焦可回车，键盘用户不需要额外安排。

**Escape 的分层在 BoardPanel 一处决定。** 它知道抽屉开没开，因此能决定这一下是关
抽屉还是关面板。抽屉自己再挂一个 window listener 会变成顺序问题——两个都会跑，
一下 Escape 关掉两层。

**抽屉存的是卡片 id，不是 Issue 对象。** 轮询会拿回新快照；存对象会让抽屉停在打开
那一瞬的旧数据上（比如 Run 已经跑完但抽屉里还写着「正在跑」）。附带好处：卡被删
掉时 `find` 自然返回 undefined，抽屉随之消失，不需要在删除路径上额外清理。

### 测试抓到的一个真 bug

耗时格式化里秒数用了 `Math.round`，于是 119.7 秒会渲成「1m60s」——一个不存在的
时间。改用 `floor`，并留了一条专门钉这个边界的用例。

### 没做的一条

「关闭后焦点回到原来那张卡」只做了一半：打开时焦点确实移进抽屉（这是「Board 的
键盘操作不被误触发」的实现方式），但关闭后焦点回到 body 而不是原卡片。要做对需要
把卡片的 DOM 引用往上传，那会在组件间牵一条只为焦点存在的线。记在这里而不是假装
做完了。
