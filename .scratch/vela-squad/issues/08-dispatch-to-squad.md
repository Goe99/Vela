# 08 — 派活时选一支 Squad，队长真的带队上场

**What to build:** 卡片上能选一支小队，点派活之后队长会话用这支队的配置起来，队长眼前出现一组具名的队员工具，并且**真的能把活派下去**。这是小队链条的第一颗贯穿子弹——必须用一次真实派活验证队员被派出来了。

不选小队时，行为与现在完全一致（派单个 Agent）。

**Blocked by:** 06 — Squad 落成 preset 文件；02 — Issue 形状扩容（小队字段）

**Status:** done

- [x] 卡片的执行配置里能选一支小队，也能选「不用小队」
- [x] 派活时会话按该小队的配置创建，沙箱档位在提交任务**之前**施加
- [x] 真实跑一次：队长确实派出了至少一个队员，队员确实产生了自己的子会话
- [x] 队员的产出汇进队长，队长正常收尾后卡片进「待验收」（不是 done）
- [x] 队长报错或被中断时卡片进「失败」；某个队员失败**不**改变卡片的落位
- [x] 失败的队员在卡片或抽屉上有可见标记 → **由票 10 交付**（详见完成记录）
- [x] 中途取消派活，队长与所有在跑的队员都停下来
- [x] 小队被删掉之后，引用它的卡片派活有明确的报错，而不是静默失败
- [x] 真实验证的过程与结果写进完成记录

## 完成记录

**两次真跑。第一次把这张票否了，第二次全绿。**

### 第一次：卡片看着成功，实际一件事也没做

建一支 `hello squad`（一个队员 `writer`，档位 danger-full-access），派一张「建一个文件」的卡。三次委派全部失败：

```text
tools.restrict() names unknown global tools "read", "glob", "grep", "write", "edit";
known global tools: writer
```

目标文件没被创建，卡片却显示 completed——因为队长自己“正常收尾”了（它写了一段报告说环境有问题）。

这恰好验证了 ADR-0018 那条规则真的在生效：**队员全部失败，卡片仍然按队长的结论落位**。但它同时暴露了那条规则的代价，也就是上面那条未勾的验收项。

根因：一份 preset 是一份**完整的** agent 平面组合，不是补丁。只写「队长人格 + 队员行」等于把 `standard` 整份换掉，队长于是一个文件工具都没有，队员白名单里的名字也全部解不开。

### 修法

组合文件改成**基准 preset 的全文 + 追加每个队员一行**（JSON flow 形式，是合法 YAML 序列项，因此不需要解析带 `!!js` 的基准）；队长的职责从 persona 行改回开场消息（多一行 persona 不是覆盖而是抛错）。顺手修了一个同类的真 bug：能力表里的 `web_fetch` 基准根本没注册（出厂给 `tool-web` 配的是 `fetch: false`），勾了「联网」的队员会以同样的方式全员失败。

### 第二次：全绿

同一支队、同一张卡：

- 组合文件 277 行，以基准的注释开头，persona 行恰好一行，队长职责一个字也不在里面
- dsh 的 preset 列表认出 `vela-hello-squad`，`trust: user`，无 broken
- 会话里**无任何 `tools.restrict()` 报错**
- 队长既调了 `writer`（派活）又调了 `read`（自己回读验收）——后者正是基准恢复后才有的能力
- 档位在 seq 3/4 从默认 `workspace-write` 被覆写为 `danger-full-access`
- dsh 自己报告该会话挂着一个子代理，标签「创建 squad-hello.txt 文件」
- 卡片进「待验收」而不是 done，token 33779
- **目标文件真的被创建了，内容一字不差**

### 哪些条是测试盖的、不是真跑盖的

诚实记下：「中途取消」与「队长报错时卡片进失败」这两条靠的是单元测试（runner 的取消与结算路径都有用例），真跑只跑了正常成功路径与一次真实失败路径（第一次）。取消的真跑验证很难自动化到可靠（需要正好卡在队员在跑的窗口里）。

### 移给票 10 的一条（已由票 10 交付）

「失败的队员在卡片或抽屉上有可见标记」要求 Vela 知道每个队员的成败，而那正是票 10（小队时间轴）必须读的同一份数据。在这张票里单做一个标记会把同一份事件解析写两遍，所以归到票 10。第一次真跑已经证明这不是锥子需求：一张看上去成功的卡可以完全什么也没做。

**票 10 已经交付了它。** 抽屉里的时间轴给每个队员一条泳道，失败的那条带 `data-tone="bad"`（红色）并写出停止原因，正常的是绿色。于是一张「看起来成功但队员全挂了」的卡，点开抽屉就能看到三条红泳道。
