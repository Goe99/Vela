# 05 — 看板级并发上限

**What to build:** 同时在跑的 Run 有一个数量上限。跑满了再点派活，Operator 会看到一条明确的「当前已有 N 个在跑，等一个结束再派」，而不是悄悄排队或者硬起第 N+1 个。

按 ADR-0018：这一层是**拒绝**，不是排队——排队会造出一个 Board 上看不见的第七种状态。

**Blocked by:** None — can start immediately

**Status:** done

- [x] 有一个可配置的上限，带合理默认值
- [x] 跑满时派活被拒绝，返回明确的错误，界面上告诉 Operator 原因与当前在跑的数量
- [x] 卡片不因为被拒而改变所在 Lane
- [x] 有 Run 结束后额度立即释放，下一次派活能成功
- [x] 崩溃恢复后额度正确：上次进程遗留的 running Run 被结算掉，不会永久占额
- [x] 并发点两次派活不会绕过上限（同时到达也只放行到上限为止）
- [x] 上限设为 0 时的行为明确并有测试固定
