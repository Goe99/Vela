# 13 — 从当前会话提取 Issue

**What to build:** 和 Agent 聊出一批待办之后，一键把它们落成 Board 上的 Issue，不用逐条重打一遍。这是「派活成本高」这个痛点的最后一块——规划对话与待办清单之间不该有手工搬运。

**Blocked by:** 04 — 创建 Issue 并在 Board 上展示

**Status:** done

- [x] Operator 在一个会话中可一键把讨论出的待办提取成 Issue
- [x] 提取出的 Issue 只进 Backlog Lane，**不会**被自动派活
- [x] 提取动作由 Operator 触发；Vela **不为此注册任何工具**，Agent 无法自行写入 Board
- [x] 提取的 Issue 默认以该会话的工作目录作为 Workspace
- [x] 落盘前 Operator 可调整标题与条目数量
- [x] 提取写入与 Board 的其他写入共用同一条串行化路径

## 完成记录：只做了一半

**做了的**：看板内的**批量建卡**——建卡表单勾上「一行一张」后可粘贴多行文本，一行一张卡片，整批落盘或一张也不落（共用同一次 mutate）。这解决了本票的核心痛点：**不用逐条重打**。Operator 从对话里复制清单粘过来即可。

**没做的**：会话内的「一键提取」入口，以及自动把该会话的工作目录当作 Workspace。两者都需要一个 **session-scoped slot entry**（例如 `conversation.session.header.actions`）才能拿到当前会话与它的 cwd——而 Board 面板是 root scope 的，定义上就不知道“当前会话”。那个接缝的 props 形状我未取证，不想靠猜实现。

**现状的代替**：Workspace 字段默认预填为当前筛选中的那个，否则是最近用过的那个，因此多数时候不用手填路径。

## 补：会话内的一键提取做出来了

第一轮把这两条推掉的理由是「那个接缝的 props 形状我未取证，不想靠猜实现」。这次
取证了，能做。

### 取到的三件事（都有源码原文）

- **`conversation.session.header.actions`** 是一个会话作用域的 list slot。官方自己的
  `session-log-export` 就挂在同一组（它用的是相邻的 `.utilities`）。
- 会话作用域的 slot，框架**自动**给组件 `sessionId` 与 `useSession`（官方叫
  `SessionStandardProps`）——不经过我们自己的 inject。
- **工作目录在 `ctx.sessions.list` 里**：`SessionsPortSummary` 有 `cwd` 字段。不需要
  额外的网络调用，也不需要宿主中转。

消息文本从 `useSession()` 的快照读：用户消息的块在 `content` 里、助手消息的块在
`blocks` 里，字段名不同但里面都是块，两种都得扫，漏一种少一半内容。

### 界面是「摆候选让人勾」，不是自动建卡

建卡权归 Operator（ADR-0012），所以提取只把候选摆出来。提取规则也因此偏向宽松地捞：
漏掉一条真待办，人得自己重打；多捞一条垃圾，人只是不勾它。两类错误的代价不对称。

只认列表行（`- `、`* `、`1. `、`（1）`），刻意**不**认散文裸行——否则整段说明的每一行
都会变成候选。已经打勾的 `- [x]` 排掉：它记的是做完了。围栏代码块整段跳过，未闭合的
围栏按「一直开到结尾」处理——模型输出被截断时很常见，宁可少捞也不要把半个配置文件
变成一堆卡片。

### 提取时抓到的一个真 bug

规则原本要求列表标记后面必须跟空格，于是 `（3）最后发版`、`1.先跑一遍` 这类**中文
习惯的写法全部漏掉**。改成：符号标记（`-` `*` `+`）仍要求空格（否则「-减去两个字段」
这种行文会被当成列表），编号标记的空格可选。

### 没验到的一条：端到端点击

**按钮在真实界面里可见并可点，这条没有验证。** 浏览器代理两次都没能把会话界面打开
到可交互的状态。我随后想退一步验「客户端 bundle 里有没有这段代码」，结果那个判定
脚本本身不成立——连已知能用的侧边栏按钮都扫不到，说明客户端插件是运行时动态加载的，
不走那些静态脚本。那个无效脚本已删掉，没留下一个会误导下一轮的假证据。

**已经有的支撑**：提取算法 22 条单元测试；组件的样式钩子与两套色板覆盖有测试钉住
（提取块长在宿主的会话头里、不在 Vela 面板底下，色板选择器必须单独把它列进去，否则
里面所有 var() 都解不开）；类型全绿；构建产物里 slot 注册与组件都在。

**缺的那一环**：没有人真的点过它。

### 顺带修掉的一个真问题

「建 N 张卡」那个按钮原本硬写了 `color: #ffffff`。夜间的强调色是亮靛蓝，配白字读不清。
是「规则体只引用变量，不直接写颜色」那条测试抓到的——改成色板里的 `--vela-accent-text`，
它在夜间正是深色。
