# 02 — OKF 文件格式地基（纯逻辑）

**What to build:** 把「一篇 Recap 在磁盘上长什么样」这件事做成纯逻辑：读得懂、写得出、看得出可不可信、看得出过没过期，外加索引与更新历史的生成。做完这张票，手写一个 Memory 目录丢给它，它能列出每篇的信任等级与陈旧状态。

**这张票刻意不是一条纵切。** 文件格式是后面每一张票共用的那一层地基，改晚了要重写磁盘上所有文件；先把它钉死，代价最低。零第三方依赖、纯函数，风格对齐 `src/domain/` 现有文件（ADR-0023）。

**Blocked by:** None — can start immediately

### 受控子集比票上写的略宽，且这是有意的

票上写的是「`sources` / `verified` 两种固定形状的对象数组」。实现按**形状**而不是按字段名定义：标量、标量数组、一层对象、一层对象的数组。差别在于别人知识包里同形状的自定义键也能读得懂——认字段名会把它们读成错误。ADR-0023 已补注这一条。

### 实现里派生出的几条纪律（都有测试锁住）

- **形如数字的字符串必须带引号写出。** 否则 `title: "3"` 往返一轮就变成数字 3。
- **同一个键出现两次报错，不是后者覆盖前者。** 覆盖会让「文件里明明写着两个值」变成没人知道的丢数据。
- **`status` 写着不认识的值时按 `draft` 读。** 宁可低估信任：把看不懂的状态读成「已稳定」会让未审的东西进召回。
- **`stale_after` 到期当天还不陈旧。** 读作「这一天之后陈旧」，边界含在有效期内。
- **`markVerified` 幂等。** 对账会反复调它（ADR-0025），不幂等就会让一篇文档长出一堆一样的审核行。
- **更新历史读不懂时抛错而不是覆盖。** 它是唯一重算不出来的东西——索引可以从 Recap 重算，"谁在哪天删了哪一篇"重算不出来。

### 一个被测试抓到的实现 bug

「头部没有闭合」这条错误原本报的行号少 1（把 0 起的下标当成了 1 起的行号）。写测试时顺手断言了行号，因此当场暴露。

### `vela_run` 为什么是扁平的

一次执行的机器可读事实收在 `vela_run` 一个键下，但里面全是扁平标量（`input_tokens` 而不是嵌套的 `usage: {...}`）。两个理由：头部解析只认一层深；这些数字的唯一用途是被脚本汇总（票 08），扁平反而更好 grep。逐个文件的读写明细进正文——那是给人看的。
