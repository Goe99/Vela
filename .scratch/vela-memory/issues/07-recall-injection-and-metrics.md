# 07 — 召回注入与可见性，外加指标埋点

**What to build:** 派一张卡时，Vela 自动把这个 Workspace 里**人审过的**复盘带上：先给一份极小的索引（每篇一行标题），Agent 按需展开正文，展开有预算上限。注入的段落带明确标题，与任务正文用分隔线隔开，Operator 能在卡片上查到「这次实际给它看了什么」——索引里列了哪些、真展开了哪几篇。同时把三个指标数出来存进复盘文件，为下一张票的对比实跑准备口径。

**Blocked by:** 05 — Gate 联动：验收同时裁定复盘可不可信

## 完成记录

新增 `src/domain/okf-recall.ts`（纯逻辑：筛选、排序、预算裁剪、拼注入文本）与 `tests/domain/okf-recall.spec.ts`（25 项）。执行器在提交任务前读候选、注入、并在提交成功后自增引用计数。全量 **654 项测试通过**，host 与 test 两个 tsc program 干净。

### 那条没勾的验收

「卡片上能查到这次给它看了什么」的**数据**已经有了：每篇复盘的 `vela_run` 里记着 `recall_indexed` / `recall_expanded` / `injected_chars` / `recalled_chars`，而复盘本身是人能直接读的 Markdown。缺的是把它摆在卡片上的界面——那属于票 06，被另一个写者占着的 `styles.ts` 挡住了。

### 注入洞见，不注入账本

展开正文时**去掉「客观足迹」那一段**。理由：足迹是账本（读了几次文件、跑了哪些命令），它对 Operator 有用（可核对），对下一次执行没用，而它往往比洞见还长。这一条同时改善了压缩率——但它不是为了数字好看，是因为把账本喂给下一个 Agent 本来就没有意义。

### 「stable」与「人审过」两个都要

筛选条件写的是 `status === 'stable' && trust === 'human-reviewed'`，看起来冗余（Vela 自己写的文件里两者同时出现）。但一份**手改过**的文件可以写着 `stable` 却没有任何审核记录，那种「自称稳定」不该被当成人审过。宁可漏，不可错喂。

同理，没记工作区的复盘一律不参与召回：认不出它属于哪个仓库，就不该把它喂给任何仓库。

### 压缩率的分母定在哪

`recalled_chars` 取**索引里那几篇**正文的全文字符数，而不是展开的那两篇。理由：压缩率要回答的是「不做渐进披露、把候选全文塞进去会是多少」，而候选就是索引里那一批。测试锁住了这个口径——它是要写进简历的数字，不能有两种算法。

顺带一条：候选数 ≤ 可展开数时**没有压缩**（全都展开了），此时注入甚至比全文略长（多了索引与说明）。写测试时先按「总是有压缩」断言，红了才想清楚这一点。

### 引用计数的时机

只在正文真被展开时自增（进索引不算），**且要等任务提交成功之后**。提交失败的那一次，Agent 从未看到这些经验，给它记一次引用是假账。

### 一个真 bug

召回事实存到了在途状态上，但 `landRecap` 组装事实时忘了传下去——复盘里因此没有 `recall_*` 字段。测试直接抓到了。这类「存了但没传」的漏在类型系统里完全不报错，因为那几个字段都是可选的。
