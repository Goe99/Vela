# 07 — 召回注入与可见性，外加指标埋点

**What to build:** 派一张卡时，Vela 自动把这个 Workspace 里**人审过的**复盘带上：先给一份极小的索引（每篇一行标题），Agent 按需展开正文，展开有预算上限。注入的段落带明确标题，与任务正文用分隔线隔开，Operator 能在卡片上查到「这次实际给它看了什么」——索引里列了哪些、真展开了哪几篇。同时把三个指标数出来存进复盘文件，为下一张票的对比实跑准备口径。

**Blocked by:** 05 — Gate 联动：验收同时裁定复盘可不可信

**Status:** ready-for-agent

- [ ] 候选集只有一种来源：**同一个 Workspace、人审过、未废弃、未陈旧**
- [ ] 按人审时间倒序，索引最多 10 篇；正文最多展开 2 篇、合计不超过 4000 字符
- [ ] 超预算时截到最后一个完整段落并标注已截断，不硬切在半句话上
- [ ] 三个上限写成常量并由测试锁住
- [ ] 注入段落带标题、与任务正文用分隔线隔开；普通卡与小队卡都注入，小队卡里排在队长职责之后
- [ ] 一篇的引用计数**只在正文被真正展开时自增**，进索引不算
- [ ] 卡片上能查到这次注入的两层内容（索引列了哪些、展开了哪几篇）
- [ ] 指标存进这次的复盘文件，不另建统计存储：重复读文件次数、注入压缩率、输入 token 与缓存读 token（**分列不合并**）
- [ ] 重复读文件次数的口径是「同一绝对路径第 2 次起算」，读文件类工具的名字取自票 01 的取证结果，不硬编码猜测
- [ ] 记忆库没配置或候选集为空时，派活文本与现在**一字不差**——没有记忆就不该有任何多余段落
