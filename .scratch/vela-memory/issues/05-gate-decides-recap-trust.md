# 05 — Gate 联动：验收同时裁定复盘可不可信

**What to build:** Operator 在待验收的卡片上按接受，同一个动作里这次的复盘被升成「人审过的」——文件里真的多出一行记录，谁在何时审的。卡片上有一个默认勾上的「这篇复盘值得留」，取消勾选表示交付算数但这篇不要。退回则复盘留在未验证，等这张卡重跑、新的一篇落盘时，被退回的那篇标成废弃：文件还在，但不再参与召回。

**这是整个模块的核心卖点**：落地即可说「验收闸门与信任分级联动」。同时它是唯一需要处理双写的地方——看板快照与记忆文件不可能一起原子写完（ADR-0025）。

**Blocked by:** 03 — 成功的执行落下一篇复盘

**Status:** ready-for-agent

- [ ] 验收接口接受「这篇是否值得留」，缺省为留
- [ ] 接受且保留 → 文件里追加人审记录并置为 `stable`，推导出的信任等级变成 human-reviewed
- [ ] 接受但不保留 → 交付照常进 Done，复盘留在未验证并标废弃
- [ ] 退回 → 复盘留在未验证，卡片回 Todo
- [ ] 重跑落新篇时，把上一篇被退回的标成废弃（不删、不覆盖）
- [ ] **顺序固定：先改看板快照，再回写文件**；看板是真相
- [ ] 回写文件失败时，卡片**仍然进 Done**，只记一条警告
- [ ] 对账能把漏写的人审记录补上（插件启动时、打开记忆页时各来一次），且**不新增快照字段、不升快照版本**——「在 Done 且文件仍是草稿」这个组合本身就是待补的信号
- [ ] 标成废弃的那篇不会被对账误补成人审过
- [ ] 状态机测试覆盖：接受 / 接受但不留 / 退回 / 退回后重跑 / 回写失败后对账补齐，五条路径
