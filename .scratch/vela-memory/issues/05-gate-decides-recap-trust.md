# 05 — Gate 联动：验收同时裁定复盘可不可信

**What to build:** Operator 在待验收的卡片上按接受，同一个动作里这次的复盘被升成「人审过的」——文件里真的多出一行记录，谁在何时审的。卡片上有一个默认勾上的「这篇复盘值得留」，取消勾选表示交付算数但这篇不要。退回则复盘留在未验证，等这张卡重跑、新的一篇落盘时，被退回的那篇标成废弃：文件还在，但不再参与召回。

**这是整个模块的核心卖点**：落地即可说「验收闸门与信任分级联动」。同时它是唯一需要处理双写的地方——看板快照与记忆文件不可能一起原子写完（ADR-0025）。

## 完成记录

`tests/memory.spec.ts` 增至 40 项全绿（新增两组：验收裁定、对账补写）。测试走 **HTTP 主接缝**（`handleApi`），因此覆盖的是 Operator 真正会碰到的那条路径，而不是内部函数。

### 快照版本没有升，这是设计的一部分

对账要回答「哪些卡验收过但文件没写成」。本来以为要在快照里记一个「待补」标记，但**现有数据已经够了**：卡在 `done` 且那篇复盘仍是 `draft` = 待补。`deprecated` 表示「Operator 故意不要这篇」，因此与「没写成」天然可区分，不会被误补——有测试锁住这一条。

于是 `BOARD_VERSION` 不用动，也不需要迁移。少一个字段就少一个日后要解释的状态。

### 「接受但不留」为什么要标废弃

ADR-0025 写的是「留在未验证并标废弃」。实现时想过只留 draft 不标废弃，但那会让这篇永远摆在候选集边缘：它没被拒（卡片进了 Done），也没被审，于是任何「把 draft 也纳入召回」的未来改动都会悄悄把它喂回去。标废弃是一个明确的墓碑。

### 重跑时标废弃的范围

扫目录找同一张卡**所有** `runSeq` 更小且仍是 `draft` 的复盘，而不是只看相邻那一篇。一张卡可能连着退回三次；只处理相邻的会把中间几篇留在灰地带。已经 `stable`（人审过）的不动——一张卡验收过后又被重新派活，旧那篇经验仍然作数，有测试锁住。

### 写链上的一个坑

`landRecap` 内部要调「标废弃」，而两者都走同一条串行写链——直接复用公开方法会**自己等自己，死锁**。修法是把每个操作拆成「走链的公开方法」与「不走链的本体」，链上的调用方只用后者。

### 测试里暴露的竞态（值得记住的一条）

「重跑后旧篇被标废弃」第一次跑是红的：我用「记忆库里有 2 篇文件」当同步点，但那只是这一批写入的第一步，标废弃在后面。修法不是加 `sleep`，而是给写链加一个 `settled()` 入口等它排空——**用轮询文件当同步点，测的就成了写入顺序的巧合**。

### 还差一处对账触发点

ADR-0025 说对账在两处触发：插件启动时、打开记忆页时。前者已接（`index.ts` 启动链路）。后者要等票 06 的记忆页——那张票被另一个写者占着的 `styles.ts` 挡住了。
