# 03 — 成功的执行落下一篇复盘

**What to build:** Operator 配好记忆库路径，派一张卡，Agent 干完，磁盘上出现一篇能直接读的 Markdown：Agent 交付的结论与坑写在正文，碰过哪些文件、跑过哪些命令、用量与耗时由 Vela 自己填。不配路径则整个功能不存在，一个文件都不写。

这张票同时打通两件事：派活文本里那段「收尾要求」（不然 Agent 不知道要按格式交付），以及结算时从会话事件里取正文并落盘。**它是第一张能往简历上写东西的票**——落地即可说「Run 摘要自动沉淀为 OKF 知识包」。

**Blocked by:** 01 — Spike：取证会话事件里的正文与工具足迹；02 — OKF 文件格式地基

**Status:** ready-for-agent

- [ ] 新增 `memoryPath` 配置：绝对路径、显式配置、**不回落当前目录也不猜 DSH 家目录**（ADR-0022）
- [ ] 没配 `memoryPath` 时，落盘路径上一行代码都不执行，也不建任何目录
- [ ] 派活文本里多出一段带标题的「收尾要求」，与任务正文用分隔线隔开（ADR-0027）
- [ ] Run 成功结算后，磁盘上出现一篇 Recap，落在按 Workspace 分的子目录里，文件名带卡号与第几次执行
- [ ] 正文三段（结论 / 做了什么 / 坑与注意）来自 Agent 收尾的围栏块；客观足迹段由 Vela 从会话事件里数出来
- [ ] Agent 没交付围栏块时，正文留空并**明确标注**「这次没有交付收尾块」，不伪造内容
- [ ] Agent 在块里写的 `verified` / `status` 之类的信任字段**一律丢弃**（ADR-0021）
- [ ] 落盘即 `status: draft`、`generated.by: vela/<version>`、`stale_after` 为落盘日 + 90 天
- [ ] 工具足迹在执行期间攒在内存里，不落盘；与实时用量同款
- [ ] 写盘失败只记一条警告，**绝不影响 Run 结算**，也不产生未处理的 promise 异常
- [ ] 更新历史里追加一行
- [ ] 记录首批样本：模型按围栏格式收尾的命中率（几次里中了几次）——命中率太低要回报，并把「收尾要求」写得更硬
