**What to build:** Operator 配好记忆库路径，派一张卡，Agent 干完，磁盘上出现一篇能直接读的 Markdown：Agent 交付的结论与坑写在正文，碰过哪些文件、跑过哪些命令、用量与耗时由 Vela 自己填。不配路径则整个功能不存在，一个文件都不写。

### 那条没勾的验收

「模型按围栏格式收尾的命中率」需要真跑才有样本，而这一轮全程没有真实派活（记忆库落盘链路是用 fake harness + 真实文件系统验证的）。**这条留给票 08 的对比实跑一并测**：那时会有 10 次真实执行，命中率是现成的副产品。现在写任何数字都是编的。

### 与另一个写者的语义冲突（**需要你裁决**）

实施期间这个工作区里有另一个写者在做「小队角色模板」，他给队员职责追加了一句「结束时，你的最后一条消息用一两句话说明：做了什么、结果如何。这段话会显示在任务卡片上」。

**这和本票的「收尾要求」撞了**：两边都在让 Agent 收尾时做总结，一边要一两句话进卡片，一边要一个 `vela-recap` 围栏块进记忆库。两个指令同时到达 Agent 时，它大概率只照一个做。这需要人来定：合成一条（围栏块里已经有「结论」段，卡片可以直接取它），还是明确分工。本票没有动他的文件。

### 派活文本的形状

原来 `buildPrompt` 只有「小队卡」一个例外，现在是两个（ADR-0027）。实现上改成拼段落：小队职责、收尾要求、任务，段间用 `---` 隔开。**没配记忆库时一段都不加，输出与从前逐字节相同**——有测试锁住这一条，因为它是「不悄悄注入」的底线。

收尾要求里写了一句「不要在块里写状态或验收字段——那由验收决定，不由你声明」。两头都做：告诉它别写，解析时也丢掉。只靠后者会让它反复写一个没用的字段。

### 足迹是怎么数的

`read` 工具 + `file_path` 参数（票 01 取证）算读；除 `read` 外带 `file_path` 的算写；带 `command` 参数的算命令，最多记 20 条、每条截到 200 字。**写文件的工具名尚未取证**，所以「写」是按排除法认的——真跑后要校对。

### 一个刻意的顺序

复盘落盘接在快照结算之后、自动重试**之前**。放在重试之前是必须的：否则第 N 次的复盘会晚于第 N+1 次开跑，票 05 要的「重跑时把上一篇标废弃」就会作用在还没落盘的文件上。

### 踩到的坑

- 测试清理临时目录时撞 `ENOTEMPTY`：结算是 detached 的，用例返回后写链还在落盘。`rm` 加 `maxRetries` 解决，而不是在每个用例里等静默。
- 我自己的两次替换把中文写坏了两个字（`拒绝`→`拒绍`、`拖垮`→`拖垂`），读回文件才发现。**教训：改中文注释后必须读回确认**，工具链在某些替换里会把字换掉。
