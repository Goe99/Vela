# 04 — 失败与中断的执行只落客观复盘

**What to build:** 一次执行报错、超时、被取消、或因为进程被杀而对账成中断，同样在磁盘上留下一篇 Recap——但只有 Vela 自己数得出来的部分：碰过哪些文件、跑过哪些命令、报了什么错、用量与耗时。Operator 打开那张卡能看到「上次是在这个文件上撞的」，而这条记录**永远不会被喂进下一次执行**（ADR-0026）。

**Blocked by:** 03 — 成功的执行落下一篇复盘

**Status:** ready-for-agent

- [ ] 四种非成功收尾各落一篇客观 Recap：报错、超时、被取消、对账出来的中断
- [ ] 正文三段留空并标注原因（超时 / 被取消 / 上次进程结束时结果未知），**不放 Agent 的收尾正文**
- [ ] 标签里带 outcome，凭它就能把这类记录从召回候选里筛掉
- [ ] 永远停在 `status: draft`，不会因为任何操作升级——失败的卡不进待验收，也就没有人来审它
- [ ] 用量缺失时写「未知」而不是 0（与现有的用量态度一致）
- [ ] 对账路径（上一个进程留下的在跑 Run）也会落盘，且不因为拿不到正文而失败
- [ ] 打开一张失败的卡能看到这篇客观记录
