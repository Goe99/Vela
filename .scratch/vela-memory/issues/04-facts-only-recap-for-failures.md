**What to build:** 一次执行报错、超时、被取消、或因为进程被杀而对账成中断，同样在磁盘上留下一篇 Recap——但只有 Vela 自己数得出来的部分：碰过哪些文件、跑过哪些命令、报了什么错、用量与耗时。Operator 打开那张卡能看到「上次是在这个文件上撞的」，而这条记录**永远不会被喂进下一次执行**（ADR-0026）。

## 完成记录

`tests/memory.spec.ts` 增至 28 项全绿。

### 唯一需要真改代码的地方是对账

成功与失败路径共用同一处落盘，因此票 03 做完后，报错/超时/取消三种收尾**已经**自动落客观复盘（正文按 outcome 分别标注、标签带 `outcome:*`、`status` 永远 draft）。这张票真正的缺口只有一个：

**`reconcile()` 绕开了结算。** 它直接 `store.mutate` 把上一个进程留下的 running Run 记成 interrupted，因此不经过 `settle()`，也就不会落复盘。修法是在对账循环里补一次落盘（`landInterrupted`）。这个缺口很容易漏——两条路径写同一个状态，但只有一条挂着落盘。

### 对账落下的复盘为什么足迹是空的

那些计数（读了几个文件、跑了几条命令、用了多少 token）只活在上一个进程的内存里，现在无处可取。因此写 `files_touched: 0` 与**不写** `input_tokens`：前者是真的没有记录，后者是「未知」。与 ADR-0011 对用量的处置同一条态度——缺失表示未知，伪造成 0 会误导。

留下的仍然有用：这张卡曾经跑过一次、什么时候起跑的、跑在哪个会话上、结果未知。Operator 想知道的第一件事就在里面。

### 失败说明的口径抽成了常量

`INTERRUPTED_FAILURE` 现在被两处用到（写进快照的 `failure`，与写进复盘的 `description`）。抽成常量而不是各写一份字面量：两处只要有一处改了措辞，Operator 就会在卡片和复盘里看到两句不一样的话，而它们说的是同一件事。

### 顺带锁住的一条

「不认识的结束原因归为报错，不会静默当成成功」——`outcome.ts` 早有这条纪律，但此前没有测试从复盘这一侧确认它。现在有了：一个 `kind: '天知道'` 的结束事件必须落成 `outcome:error` 的标签。把未知当成功会让一篇没人审过的复盘悄悄流进待验收，是这个模块最坏的失败模式。
