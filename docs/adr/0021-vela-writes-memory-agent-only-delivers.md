# Recap 由 Vela 写，Agent 只交付正文

一个 Run 结束时，**Vela 是 Memory 的唯一写手**。Recap 的正文来自 Agent 收尾那条回复里一段约定格式的块——Vela 从自己已经订阅的会话事件流里取（`assistant/message` 事件带着完整的 `content`，不只是用量）；文件的客观部分（工具足迹、用量、耗时、来源会话、生成者与时间）由 Vela 自己填。**Agent 若在正文里写了 `verified`、`status` 这类信任字段，一律丢弃。**

这是 ADR-0007「Agent 有权交付，无权宣布通过」在知识资产上的同一条原则：Recap 的内容是交付物，它可不可信不是交付者说了算。信任分级如果能被生产者自己填写，分级就地失效。

## Considered Options

- **让 Agent 自己把 Recap 写进 Memory** — 拒绝。它能顺手把「已经被人审过」写上，Trust Level 立刻变成一句自证；写没写、写成什么形状也不受控（模型跑偏就是一个空目录或一堆半截文件）；还要为此给它开一条 Memory 目录的写权限，与 ADR-0012「Agent 无权写 Board」是同一类问题的同一个答案。
- **Vela 自己调模型生成摘要** — 拒绝。拿不到模型：宿主给第三方插件的 apiProxy 里，`llm` 域只能列举 provider 与模型，没有补全调用（ADR-0015 只给到会话域）。绕路的办法是为摘要另开一个会话，那等于凭空多一次计费执行，还得替它准备上下文——而 Agent 自己在收尾时写一段，边际成本几乎为零。
- **纯客观拼装，完全不用 Agent 的输出** — 采纳了一半。只靠 Vela 自己看到的事实（碰了哪些文件、跑了哪些命令、结果如何）能拼出一篇绝不胡说的文档，但那是账本不是经验，召回它对下一次执行没有帮助。因此客观部分照此拼，**洞见留给 Agent**。

## Consequences

`src/dsh.ts` 要新增 `assistant/message` 的 data 形状声明。按该文件自己的规矩，每个签名都必须对着真实运行时取证过——目前这个形状只在 dsh 源码里读到（`packages/core/session/src/types.ts` 的 `SessionEventMap`），**实跑取证是实施的第一步**，不是可以跳过的一步。

Agent 没照格式收尾时，Recap 只落客观部分，正文留空并标明「这次没有交付收尾块」——不伪造正文，与 ADR-0011「用量缺失表示未知，不伪造成 0」是同一种态度。

派活文本里会多出一段 Vela 自己的约定（「收尾时按这个格式写」），这与 `buildPrompt` 现有的「普通卡不包装任何指令，Agent 的行为应由 preset 决定」相抵。本 ADR 不预设那条冲突的解法，它由关于注入的决策单独回答。
