# Gate 的一次判定同时裁定 Recap 的信任等级

Gate 上的接受与退回不只裁定这次交付算不算数，同时裁定这次的 Recap 可不可信：**接受** → 往 Recap 里回写一条 `verified`（`human:operator` 加时间），它的 Trust Level 因此从 unverified 推导为 human-reviewed，可以参与 Recall；**退回** → Recap 留在 unverified，且当这张卡重跑、新的一篇落盘时，把被退回的那篇标成 `status: deprecated`——文件还在，但不再参与 Recall。

验收时默认连记忆一起收，卡片上留一个默认勾上的「这篇复盘值得留」；取消勾选表示交付算数但这篇不要，那篇同样留在 unverified 并标废弃。

## Considered Options

- **一个按钮，接受即连记忆一起升级，没有例外** — 拒绝。一按就把写得烂的摘要也升成「人审过的」，而 human-reviewed 是这个模块唯一有分量的信号，稀释它等于把卖点做空。
- **交付与记忆做成两个独立判定** — 拒绝。会长出「交付退回但记忆留下」这种每次都要解释一遍的组合，且每张卡都要做两次决定。
- **被退回的那篇直接删掉** — 拒绝。被人否过的 Recap 是反面证据，它记着「这条路试过、不通」。删了可惜，召回了有害；标废弃刚好落在中间，用的还是格式自带的字段，不用自造。
- **重跑时覆盖同一篇** — 拒绝。会抹掉「这件事试了三次」这个事实，而那往往比任何一次的正文都值钱。

## Consequences

**Board 快照是真相，Memory 是可对账补齐的那一份。** 一次接受要改两份存储（卡片进 Done、Recap 写 `verified`），两者不可能原子完成。顺序固定为先改快照、再回写文件；回写失败只记一笔警告，由下次启动或下次打开记忆页时的对账补上——与 `reconcile` 收拾「上一个进程留下的 running Run」是同一套态度：不假装写盘不会失败。

反过来不成立：**不能让 Memory 成为真相。** Trust Level 必须真的落进文件，否则把记忆库拷给别人时就看不出哪些经过人审——那是 OKF 最值钱的地方，也是「记忆不绑宿主」这句话唯一的实证。

Gate 的词条已跟着改（见 CONTEXT.md）：它现在裁定两件事，不是一件。
