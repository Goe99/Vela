# Token 用量在 Run 结束时快照进 Run 记录

Run 结束时，从其绑定的 DSH 会话聚合一次 token 用量，并把结果写入 Run 记录。Board 后续读取该快照，不再回溯会话日志。进行中的 Run 另行订阅会话事件显示实时进度，该实时计数不持久化。

**这是对 ADR-0003「执行侧真相留在 DSH 会话、不双写」原则的刻意例外，请勿当作 bug 修掉。** 豁免理由是一个天然不变量：**Run 结束后其 token 用量永不再变**，因此该快照不存在失效可能——这正是安全缓存的成立条件。

## Considered Options

- **每次渲染 inspect 会话并聚合** — 拒绝。语义最纯，但 Board 上有 N 张卡片就要读 N 份会话日志，几十张卡即出现可感知卡顿，而这是主界面。
- **仅靠实时订阅维护活计数器** — 拒绝。进程重启后计数丢失，且无法为历史 Run 提供用量。

## Consequences

Run 记录中的 token 字段只在 Run 到达终态时写入一次，此后视为不可变。若 Run 未正常结束（进程崩溃、被杀），该字段可能缺失——此时应显示为未知，而非回退到实时计数或零值。历史用量的权威来源仍是 DSH 会话日志，快照只是读取优化；两者若出现分歧，以会话日志为准并重新聚合。
