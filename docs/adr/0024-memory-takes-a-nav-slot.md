# 记忆库在主导航里占一项，十二项因此变十三项

Memory 在左侧导航的「工作区」组占一项（键 `memory`，摆在 `squads` 之后、`usage` 之前），点了切到 Vela 自己画的记忆页。这让 ADR-0020 的「按 Multica 的三组十二项原样摆好」变成十三项，也让 Vela 自己画的界面从三处变成四处。

破例的理由是 ADR-0020 要防的事在这里不成立：它防的是**重画 DSH 已经有的界面**（设置、技能、agent 配置），而 Memory 在 DSH 里根本不存在——没有可以「做入口跳过去」的目的地，也没有两套实现要维护的风险。十二项是移植保真的产物，不是产品法则；而一个 Operator 找不到入口的功能等于没做。

## Considered Options

- **占用 `usage` 那个「下一期」的灰位** — 拒绝。语义不对，等真做用量汇总时还要再搬一次，那时 Operator 的肌肉记忆已经建立。
- **不进主导航，入口做在卡片里（「这次的复盘」链接）** — 拒绝。卡片里的入口只能看到这一张卡的，看不到整个库；藏在抽屉里的新功能，Operator 不会知道它存在。
- **加在「配置」组末尾** — 拒绝。记忆是工作产物，不是配置项。

## Consequences

锁归属表的那条测试要跟着改：数量从 12 到 13、键名清单加一项。**真正的核心不变量不变**——每一项都有明确归属、没有一项悬空、置灰的两种原因分得开。改掉的只是「与 Multica 逐项对照」那一条，它从此读作「十二项照 Multica 对照，外加 Vela 自己的一项」。

本 ADR 不是「导航可以随便加」的授权。日后想加项的人仍要先回答 ADR-0020 那个问题：点下去到底发生什么。
