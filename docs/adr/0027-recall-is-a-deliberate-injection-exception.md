# Recall 是刻意的第二个注入例外，注入的内容必须对 Operator 可见

`buildPrompt` 现有的原则是「普通卡不包装任何指令——Agent 的行为应由 preset 决定，不由 Vela 悄悄注入」，小队卡是第一个刻意的例外。Recall 与「收尾按格式写」是**第二个**：派活文本里会多出两段带明确标题的区块（`## 以前的经验` 与 `## 收尾要求`），与任务正文用分隔线隔开。

守住的不是「不注入」，而是**不偷偷**注入：两段都带标题，Agent 和人都能看出哪一段是 Vela 加的；并且 Operator 能在卡片上查到「这次实际给它看了什么」。

## Considered Options

- **每张卡一个「这次带记忆」开关** — 推后，不是拒绝。一上来就给开关，等于让 Operator 每张卡做一次他还没有判断依据的选择；等对比数据出来再决定要不要它。
- **把记忆做成 preset 段落或技能，而不是塞进消息** — 拒绝。这是最「不悄悄」的做法，但要碰 preset 生成，与小队组合那套「基准 + 追加队员」（ADR-0016）直接打架；而且 preset 是跨 Run 常驻的，Recall 的内容每次都不同，形状对不上。
- **静默注入，不给 Operator 看** — 拒绝。那正是原则要防的事：一次执行为什么这么做，Operator 必须能自己查出来。

## Consequences

注入按预算裁剪：先给索引，Agent 按需展开正文。因此「注入了什么」有两层——索引里列了哪些、实际展开了哪几篇。卡片上必须能看到这两层，否则压缩率这个数字无从核对，也就不该拿它对外说。
