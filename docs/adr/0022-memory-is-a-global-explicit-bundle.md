# Memory 是全局单一的知识包，路径必须显式配置

Memory 全局只有一份，内部按 Workspace 分子目录；路径经配置项显式给出，**不配置就不启用记忆功能**——不回落 `process.cwd()`，也不去猜 DSH 的家目录。这与 ADR-0006 对 Board 快照的处置同构：一个会自己建目录、自己往里写文件的功能，必须由 Operator 明确开启。

## Considered Options

- **每个 Workspace 的代码库里放一份（`.vela/memory/`）** — 拒绝。OKF「`git clone` 即搬运」的好处在这里换不到：往 Operator 的业务仓库里写文件会污染它的 git 状态、干扰 Agent 自己看 diff，还要处理「这个目录该不该进 .gitignore」这种本不属于 Vela 的问题。可移植性由「Memory 本身就是纯 Markdown，整体拷走或单独 `git init` 就能搬」提供，不需要寄居在业务仓库里。
- **塞进 Board 那份 JSON 快照** — 拒绝。Recap 是要给人读、给 `git diff`、给 Agent 按需展开的一批文档；塞进单个 JSON 就同时失掉 OKF 的两个好处：索引先行的渐进披露，和单篇独立可验收。
- **不配置也能用，默认落在 Board 快照旁边** — 拒绝。省下的一行配置换来的是「Vela 什么时候开始往哪里写文件」变成隐式行为。

## Consequences

未配置时，记忆相关的界面与接口必须明确回答「没开启」，而不是回一个空列表——空列表看起来像「还没有记忆」，对 Operator 这是两件不同的事。

Memory 与 Board 快照是两份独立存储，一次 Gate 判定要同时改动两边。两边不可能在一个原子操作里完成，因此必须指定其中一份为真相、另一份可对账补齐；这一条由关于双写的决策单独回答。

## 实现后的补注：「显式配置」落在哪一层

上面拒接了「不配置也能用，默认落在 Board 快照旁边」。那一条拒的是**代码里的回落**，不是 bundle 里的声明：

- `src/index.ts` 里 `memoryPath` 仍旧没有默认值，拿不到就整体不启用，不猜家目录、不回落 cwd。
- 具体路径写在 `cordis.patch.yml`（`dshHomePath('vela/memory')`），与 `boardPath`、`squadRoot`、`skillsDshRoot` 同一个处理——那份 patch **就是**部署层的显式声明。

为什么不让它缺省为空：那会让每一份安装都带着一个永远写着「没开启」的导航项，而 Operator 无从知道要填什么。原本担心的「自己建目录、自己往里写文件」已经被另一条约束按住：**打开时不创建任何目录**，目录只在真的要落第一篇复盘时才出现。

**代价要记住**：声明了路径就等于默认开启，而开启后派活文本会多一段「收尾要求」（ADR-0027）。不想要记忆功能的部署把 `cordis.patch.yml` 里那一行删掉即可，行为退回到与从前逐字相同。
